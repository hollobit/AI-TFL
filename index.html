AI 신뢰성을 ‘믿으라’는 문구가 아니라, 검증하고 비교할 수 있는 사실로 바꿉니다.

TFL은 하나의 claim·증거·제품 프로파일 모델을 공유하면서, 목적과 보증 메커니즘에 따라 Type I·II·III·IV를 구분하는 제안 프레임워크입니다. 현재 작업의 중심은 낮은 진입장벽과 시장 확산성을 갖는 Type II 자기선언입니다.

01 / TYPES

하나의 목적, 네 가지 병렬 메커니즘

Type은 우열이나 성숙도 단계가 아닙니다. 동일한 사실모델을 서로 다른 선언 목적·운영주체·검증 방식으로 표현합니다.

I

프로그램 기반 제3자 인증

사전 정의된 기준과 적합성 평가에 따른 인증 표시

ISO 14024-inspired · certification body · scheme rules
개념 검토
II

검증가능한 자기선언

선언주체가 정확·비오도 claim과 입증자료를 공개

ISO 14021-inspired · claim rules · ex-post substantiation
활성 제안
III

정량 신뢰성 선언

범주규칙·선언단위·benchmark·SC 42 방법을 고정해 정량값 공개

ISO 14025/EPD-inspired · PCR · independent verification
방법론 검토
IV

개발자 기술선언

모델·데이터·평가·한계·변경이력을 공급망에 전달

Model card + SC 42 lifecycle evidence · machine-readable
스키마 검토
02 / CORE

Type을 바꿔도 흔들리지 않는 공통 코어

표시 형식보다 먼저 claim의 의미, 적용 범위, 증거와 검증 주체를 구조화합니다.

공통 정보모델

  1. TR 24028·TS 5723 기반 trustworthiness characteristics
  2. 동사·정량형 claim과 필수 한정문
  3. 제품 유형별 MUST·SHOULD·MAY·N/A 프로파일
  4. 측정방법·데이터셋·버전·시점·범위
  5. SC 42 표준·규제·수명주기 연결
  6. 사람용 패널과 기계가독 JSON의 동일 사실

현재 카탈로그 범위

  1. 91  selected claims
  2. 29  trustworthiness characteristics
  3. 8  product-type profiles

03 / ACTIVE

왜 지금 Type II인가

현재 페이지의 직접 목적은 ISO/IEC 42117-2 Type II 제안을 설득하는 것입니다. 다만 그 논거와 데이터 구조는 후속 Type을 재사용할 수 있게 설계합니다.

가장 낮은 도입비용으로, 검증 가능한 정보의 공급을 먼저 만듭니다.

Type II는 인증기관과 프로그램 운영체계가 완성되기 전에도 적용할 수 있습니다. 선언 책임은 공급자에게 두되, claim 규칙·필수 한정문·입증자료·L1/L2/L3 표시·기계가독 형식으로 사후 검증과 시장 비교를 가능하게 합니다.

01형용사·절대주장 대신 검증 가능한 사실 claim
02제품유형 프로파일로 과잉·누락 선언 방지
03claim마다 증거 수준과 검증 범위를 분리 표시
04규제·조달·공급망 재사용이 가능한 JSON
